================================================================
  本地模型 · 联网插件   ——   大肥鱼本地\联网\
================================================================

【它解决什么问题】

本地部署的大模型有个硬伤：**知识停在训练截止那天，而且不会查资料**。
你问她"今天北京天气""DeepSeek-R1 什么时候发布的""英伟达最新显卡"，
她要么答不上来，要么一本正经地编。

这个插件让她能上网查。

【怎么用】

  双击 ..\大肥鱼.bat → 菜单 [5] 联网插件        （启动）
  启动后状态页会显示：联网插件 : 运行中  http://127.0.0.1:8081/v1

  然后把**客户端的接口地址**从 8080 改成 8081，就自动带联网能力了：

     直连（不联网）  http://127.0.0.1:8080/v1
     联网版          http://127.0.0.1:8081/v1   ← 填这个

  适用任何客户端：浏览器对话界面、Cherry Studio、ChatBox、沉浸式翻译、
  你自己写的脚本……只要它支持 OpenAI 格式、能改接口地址就行。

  调试（不经过模型，直接看搜到了什么）：
     http://127.0.0.1:8081/api/search?q=今天北京天气


【为什么做成代理层，而不是改 llama.cpp】

  · **任何模型通用**：代理只看 HTTP，不关心背后是 DeepSeek 还是 Qwen 还是
    你以后新下的模型。换模型、加模型，联网功能都不用重做。
  · **任何客户端通用**：不用改客户端代码，改个地址就行。
  · **不侵入 llama.cpp**：升级运行时不会把联网功能搞丢。
  · 这也是你选的那个方案。

  数据流：

     客户端 ──► 8081 代理 ──► 判断要不要联网
                          ├─ 要 ──► 必应/百度检索 ──► 把资料拼进提问
                          └─ 不 ──► 原样转发
                          ──► 127.0.0.1:8080 模型 ──► 流式吐回客户端


【什么时候会联网】

  · 句子里出现「搜索 / 查一下 / 最新 / 新闻 / 今天 / 谁是 / 是什么 / 多少钱 /
    天气 / 什么时候 / 成立于 ……」这类词
  · 带问号且不超过 60 字
  · **想强制联网**：用 `@搜索` 开头，比如 `@搜索 今天有什么新闻`
  · **不想让它搜**：把 联网配置.json 里的 enable 改成 false；
    或者把 always 改成 true 让它每句都搜（慢，但省心）


【检索式清洗（这是最关键的一环）】

  直接把口语问题丢给搜索引擎，结果会很差。实测同一件事：

     原问题「DeepSeek-R1 是什么时候发布的？只回答日期。」
        → 搜索结果 5 条里只有 1 条有用，模型照着手里的错资料答了「2026年9月2日」

     清洗成「DeepSeek-R1 发布时间」
        → 5 条里 5 条全中，模型答「2025年1月20日」✔

  所以插件会先把问题压成关键词：剥掉疑问句、剥掉"只回答日期""一句话"这类
  对模型的要求、收敛重复的同义词。效果对比（清洗后实搜）：

     今天北京天气怎么样？一句话。  →  今天北京天气        5/5 条命中
     谁是美国第一任总统？          →  美国第一任总统      4/5 条命中
     英伟达最新显卡是什么？        →  英伟达最新显卡      5/5 条命中
     iPhone 17 多少钱？简洁点      →  iPhone 17 价格      


【搜索引擎】

  默认必应（cn.bing.com，实测最快 292ms），失败自动降级到百度。
  实测可达：必应 CN / 必应国际 / 百度 / 百度移动 / 搜狗 / 360 / 百度百科
  实测被墙：DuckDuckGo、Wikipedia（这台机器的网络环境下）

  换引擎：改 联网配置.json 的 engine 为 "baidu"。


【配置文件 联网配置.json】

  enable        true    总开关
  always        false   true=每句都搜（慢但省心）
  max_results   5       送进上下文的资料条数
  timeout       15      检索超时（秒）
  engine        bing    主引擎，bing / baidu
  show_note     true    回答前加一行「（已联网检索到 N 条资料）」

  改完要重启插件才生效（控制台菜单 [6] 停、[5] 起）。


【已知情况】

  1. **推理模型的空回答不是插件的问题。**
     DeepSeek-R1 系列会先长篇思考再回答，如果 max_tokens 给小了（比如 200），
     思考就把预算吃光，正文变成空的。实测同一个问题：
        max_tokens=200 → 有时正文为空（finish_reason=length）
        max_tokens=500 以上 → 稳定有正文
     客户端里把 max_tokens 调到 500~1000 就好。Qwen 这类非推理模型没这问题。

  2. **回答质量取决于模型本身。** 插件只负责"把资料找回来、塞进上下文"，
     7B 级别的小模型偶尔仍会误读资料。换更大的模型或 Qwen2.5 会明显更好。

  3. 检索结果里若混入日期相近但内容无关的页面（比如搜发布时间却搜到 App 下载页），
     模型可能取错。清洗检索式已经能大幅缓解这种情况。


【验证记录】

  · 必应解析：5 条 / 0.7 秒      百度解析：5 条 / 1.5 秒
  · 端到端（流式）：问「DeepSeek-R1 是什么时候发布的？只回答日期。」
      → 触发联网（5 条资料）→ 答「DeepSeek-R1是在2025年1月20日发布的。」✔
  · 强制联网 @搜索「今天北京天气」→ 答出具体天气 ✔
  · 纯闲聊不触发检索 ✔
