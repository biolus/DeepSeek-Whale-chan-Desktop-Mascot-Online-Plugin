================================================================
  鲸鱼娘桌宠   ——   鲸鱼娘\
================================================================

【怎么用】

  双击  启动鲸鱼娘.bat
        → 起后端 → 检查大脑 → 叫她出来（透明、无边框、永远置顶）

  从控制台也能起：双击 ..\大肥鱼.bat → 菜单 [2]
  出不来时：双击 浏览器模式.bat（用浏览器打开，能区分是后端问题还是外壳问题）

  ★ 整个「大肥鱼本地」文件夹可以随便改名、换盘、搬到别的机器，
    脚本一律按自身位置找文件，不再依赖任何写死的路径。


【怎么跟她互动】

  · 拖她              = 拖窗口（位置会记住）
  · 双击她            = 戳一下（不带输入框了，说话请点工具栏的「说话」）
  · **右键点她**      = 弹出账本（余额 / 今日已用 / 本轮消耗 / 峰谷）
  · 点工具栏「⋯」     = 她的菜单（表情 / 换装 / 摆场景 / 演动作 / 调大小）
  · 鼠标压在她身上才收点击，其它地方**直接穿透**，不挡你干活
  · 托盘图标（右下角）＝ 显示/隐藏 · 重新加载 · 收起成小球 · 回到右下角 ·
                        低性能模式 · 打开控制台 · 彻底退出


【账本：数字对得上 DSH 的实际花费】

  数据不是估的，是直接读 DSH 自己的记账：

    ~/.dsh/sessions/<项目>/<会话>/session.v4.jsonl.zstd
        每条 assistant/message 都带 时间 + usage
        （inputTokens / outputTokens / cacheReadTokens / cacheWriteTokens）

  然后按 DeepSeek 的价折算成钱：

    今日已用 = 今天（本地日期）所有会话的 usage 合计
    本轮消耗 = 最近一条带 usage 的记录
    峰 / 谷  = 北京时间 00:30~08:30 是谷时，其余峰时；显示距切换还有多久

  ★ 账本只在**右键点她**时弹出。原版一轮答完会自动弹一次，已经关掉了
    （数据仍然照常拉好放在后台，右键时 0.02 秒就出来，不用等）。

  改价： 记忆\计价.json
    cache_hit       0.5   缓存命中输入  元/百万 tokens
    cache_miss      2.0   缓存未命中输入
    output          8.0   输出
    valley_discount 0.5   谷时折扣（0.5 = 半价）
    api_key         ""    想显示余额就填 sk-...（见下）

  关于余额：DeepSeek 的余额接口要标准 API key（sk-...），
  DSH 里存的是 OAuth 凭证、不是 API key，所以**没有动它**。
  想在小账本上看余额，自己填一个 api_key（或设环境变量 DEEPSEEK_API_KEY）。
  没填就显示「—」，不编数字。


【她会跟着本地模型的状态动】

  她本身不调用任何 LLM，只是把「AI 在干什么」渲染成动作：
    你说话→转头看你 / 模型推理→低头思考 / 逐字输出→嘴跟着动 /
    出错→黑一下脸 / 收工→伸懒腰庆祝

  这套状态原来接 DSH，现在接本地 llama-server，靠一条 SSE 事件流，
  所以「跟着 AI 实时状态走」完整保留。

  安静够久（默认 240 秒）她会自己找模型要一句话说出来。
  间隔和开关都在她「⋯」→「大脑」页签里调（默认是开的）。
  注意：主动开口也要先把模型拉起来，所以「平时不占显卡」说的是
  「她既没在主动说话、你也没在跟她说话」的那段时间。


【目录】

  鲸鱼娘\
  ├─ 启动鲸鱼娘.bat     正常启动（Electron 透明桌宠）
  ├─ 浏览器模式.bat     排查用
  ├─ server.py          后端：静态托管 + SSE 事件流 + 本地模型对话
  ├─ 账本.py            读 DSH 真实 token 用量并计价
  ├─ 网页\ pet.js / vendor\ / model\
  ├─ 外壳\              Electron 窗口的**主副本**
  └─ 记忆\              配置.json / 计价.json / 人设.txt
                        （对话.json、大脑.log 是运行后自己生成的本地记录）

  %LOCALAPPDATA%\DSWhalePet\   ← 外壳的 ASCII 运行副本
  ├─ electron\          运行时（首次启动从 外壳\ 拷过来，只需一次）
  ├─ main.js / preload.js / package.json   ← 每次启动自动同步
  └─ shell.log          外壳排障日志


【为什么有 %LOCALAPPDATA%\DSWhalePet 这个目录】

  因为 electron.exe 在**某些中文路径下会确定性崩溃**。实测（各跑 3 次）：

       <含中文的文件夹>\_etest\   ->  崩溃 0xc0000005，0/3 成功
       <纯 ASCII 路径>\abc\       ->  正常，3/3
       <中文父目录>\etest         ->  正常
       <测试目录>\sub             ->  正常
       <含中文的文件夹>2\etest    ->  正常

  崩溃模块就是 electron.exe 自己，错误偏移每次恒定。
  试过 junction 和 subst，**都会被解析回真实路径，没用**。

  所以启动时把外壳同步一份到纯 ASCII 路径再跑。
  放 %LOCALAPPDATA% 而不是某个盘根目录，是为了整包换位置、换机器都能用，
  不占 D 盘根、不需要管理员权限。

  **主体文件仍然在 鲸鱼娘\外壳\，那边是主副本。**
  改了 外壳\main.js 之后重新双击启动脚本就会同步过去。


【显存：平时不占显卡，说话才占】

  本地模型不再"开机就常驻"。默认（记忆\配置.json 的 manage_llm = true）：

    · 你跟她说话 / 她主动开口时 → 才把 llama-server 拉起来（实测 4~6 秒）
    · 一轮说完，安静 60 秒（idle_unload）→ 自动停掉 llama-server
    · 于是不聊天的时候：显存 0、GPU 占用 0

  想让它常驻显存（还要拿 8080 给 Cherry Studio 之类别的软件用）：
    · 她菜单「⋯」→「大脑」页签，点一下「显存策略：平时不占显卡」切过去
    · 或编辑 记忆\配置.json，把 manage_llm 改成 false

  注意：默认会把 大肥鱼.bat 菜单 [1] 手动起的那个也一起接管 ——
  她不说话就把它卸掉。你正拿 8080 给别的软件用就改成 false。

  「大脑」页签里还能调：主动说话开关、主动说话间隔、空闲卸载秒数
  （填 0 = 不自动卸载）。

  例外：如果你用任务管理器把后端 python 强杀了，那个已经拉起来的模型会留在
  显存里（负责按时卸载的是后端，它没了就没人卸）。双击 ..\停止AI.bat
  就收拾干净了 —— 那会把 llama-server 一起结束掉。


【为什么不让她复读】

  以前她自己开口时会把同一段话循环吐到 max_tokens 上限 —— 512 token，
  本机约 2.2 token/秒，一句复读就让显卡满载 3 分多钟。

  根因两个，都修了：

    ① 历史里只有 assistant、没有 user
       主动说话那一路只往 对话.json 塞 assistant、从不塞 user，历史变成
       清一色 assistant；模型看见十几个连续的 assistant 发言，就照着往下
       复读同一段话。之前堆过一大串一模一样的旧记录，就是证据。
       现在主动说话也记一条 user，写历史时保证 user/assistant 交替。
    ② 请求里没有任何重复惩罚
       现在带 repeat_penalty=1.18 / repeat_last_n=256 /
       presence_penalty=0.3 / frequency_penalty=0.3。

  另外三道"出话刹车"，任何一道触发就立刻断开连接 —— llama.cpp 收到
  断开就取消这次生成、马上空出显卡：

    ① 复读检测：尾部同一段（周期 10~600 字）原样重复就掐断，
       并把重复的部分裁掉、只留第一遍
    ② 正文字数上限 max_reply_chars（默认 240）
    ③ 单轮秒数上限 max_reply_seconds（默认 35）

  外加 max_tokens 收窄：对话 200、主动开口 96。


【速度：这里只有 ~2.2 token/秒，不是配置能救的】

  实测（2026-10）：R1 蒸馏 / Qwen2.5 Instruct 都是 ~2.2 token/秒；
  指定 --device Vulkan0、上下文 4096/8192 都不变。生成期间模型确实在
  显存里（约 5.4GB）、显存频率跑满、GPU 显示 100%，
  但功耗只有 34 W —— GPU 大部分时间在空等。
  这是 运行时\ 里这个第三方 Vulkan 运行时的 kernel 效率问题。
  真要提速得换 CUDA 版（见 ..\说明.txt 第七节，缺三个 CUDA dll）。
  在那之前，桌宠已经按 2.2 token/秒 把话说短、把显卡及时放掉。


【这次修了什么】

  ① 托盘图标点不动
     createTray 里原来有 setInterval(rebuild, 1500) —— 每 1.5 秒重建一次
     原生菜单。Windows 上 setContextMenu 会重建整个原生菜单，菜单正开着时
     被换掉就点不动了。改成只在状态真的变了时才重建。
     另外加了兜底图标：icon.png 读不到时用一个内置小图，不会再出现
     「看不见也点不着」的空托盘。

  ② 无法拖动
     拖动依赖主进程每 90ms 问页面一次「鼠标下面是不是她」。页面没加载好
     （比如整合包改名后后端还指着旧路径）时这个询问一直失败，窗口就永远
     保持点击穿透 —— 表现就是既点不动也拖不动。
     现在页面能正常加载，实测把鼠标移到她身上命中检测零失败。
     另外给命中检测加了失败计数日志，再出这种哑巴故障能立刻看出来。

  ③ 账本对不上 DSH 的花费
     原来返回的是假数据（写死 0）。现在读 DSH 自己的 token 记账再按
     DeepSeek 的价折算，见上面「账本」一节。

  ④ 说完话自动弹账本
     关掉了两处自动弹出（一轮结束、hud-turn 事件）。账本改成只在她身上
     右键时弹。

  ⑤ 整包找不到路径
     所有写死的绝对路径都去掉了，改成按脚本自身
     位置推导 + %LOCALAPPDATA%。以后随便改名、换盘、换机器都能跑。

  ⑥ 底下「说话 / ⋯ / – / ↗」按键点不准（2026-10 修）
     病根是**屏幕坐标用错了**：外壳为了让她的视线跟着鼠标全屏转，每 16ms 用
     sendInputEvent 往页面里注入一个假的 mouseMove，而那个坐标是「把整块屏幕
     归一化再乘窗口宽高」—— 根本不是光标在窗口里的位置。可页面的命中判定
     （决定窗口要不要点击穿透）正是按 clientX/clientY 算的，于是每 16ms 就被
     一个假坐标带偏一次，穿透状态疯狂翻转：按钮按到一半窗口切成穿透，click 的
     up 就落到桌面上了，看着就是「点了没反应」。
     现在外壳改成走 IPC 只喂一个只读的全局光标（只给视线用），命中判定重新
     只认真实鼠标事件；页面那边又加了两道保险：
       · 按住鼠标期间命中锁成 panel，click 不可能被切成两半
       · 每 500ms 强制汇报一次，把外壳那条「按窗口坐标算」的兜底彻底压住
       · 窗口失焦不再硬报 none，改成按最后一次已知位置重算

  ⑦ 拖动抽搐 / 时好时坏（2026-10 修）
     两个毛病叠在一起：
       · 拖动被两边抢着做 —— 外壳搬窗口，页面自己也在搬 root，各搬各的
       · pet.js 在按下时调了 preventDefault，而取消 pointerdown 之后浏览器
         **不会再补发 mousedown**，外壳恰恰是靠 mousedown 才开始搬窗口的 →
         整窗拖动实际上一直是死的，你拖的只是她在一个 560×900 的小窗里挪，
         顶到边就动不了、还跟吸附动画打架
     现在分清楚了：桌面外壳里「拖她 = 外壳搬窗口」，页面里绝不再动 root，
     也不再 preventDefault，不播吸附/惯性；「是拖还是点」改用屏幕坐标判断
     （窗口跟着鼠标走时 clientX 几乎不变，拿它判断只会永远判成"点"，松手就
     莫名其妙戳她一下）。浏览器模式（没有外壳）保持原来的页面内拖动。


【起不来怎么办】

  1. 先双击 浏览器模式.bat
       能看到她  = 后端没问题，是外壳的问题
       看不到她  = 后端或模型有问题（看 记忆\大脑.log）

  2. 看外壳日志 %LOCALAPPDATA%\DSWhalePet\shell.log
       loadURL 那行有       = 外壳正常，页面已加载
       没有这个文件         = 外壳根本没跑起来（路径或权限问题）
       「命中检测失败」很多 = 页面没加载好，她不能点也不能拖

  3. 崩溃记录：事件查看器 → Windows 日志 → 应用程序 → electron.exe
